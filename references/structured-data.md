# Structured Data Reference

Use this reference for blog/article structured data grounded in official sources.

## Primary Sources

- Google Search Central structured data documentation and rich result feature docs.
- Rich Results Test.
- Schema.org vocabulary.

## Baselines

- JSON-LD is generally the preferred implementation format for Google.
- Mark up only content that is visible to users on the page.
- Use types and properties that match the actual content.
- Validate before claiming eligibility.
- Structured data can help search engines understand content, but it does not guarantee rich results.

## Blog/Article Types

For ordinary blog posts, consider:

- `BlogPosting` or `Article`
- `BreadcrumbList` when the page has a visible breadcrumb trail or clear site hierarchy
- `Organization` / `WebSite` at site level when appropriate
- `Person` author data when author identity is actually shown and relevant

## Restricted or Volatile Areas

- FAQ rich result eligibility has changed over time. Check current Google documentation before recommending FAQ markup for rich result purposes.
- HowTo rich result support has changed over time. Check current Google documentation before recommending it.
- Product, Review, LocalBusiness, Event, and Video structured data have specific required/recommended fields and policy constraints. Read current Google feature docs before suggesting them.

## Common Problems

- schema claims not visible in the article
- placeholders left in JSON-LD
- fake ratings, fake reviews, or invented author credentials
- mismatched `dateModified`
- image URLs too small or inaccessible
- duplicate or contradictory structured data generated by CMS/plugins

## Output Guidance

When recommending schema, state:

- `Purpose`
- `Official source to verify`
- `Visible page evidence`
- `Suggested JSON-LD or CMS setting`
- `Validation step`
